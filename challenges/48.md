## Day 48 Challenges

### Challenge 1 - Workflow Audit

#### Scenario

Assume there is one or more Workflows in the MiniShop repository; however, you are not yet certain what checks they perform.

If a Workflow is not found, record its absence as an audit result.

#### Task

Create an audit table that specifies the following for each Workflow:
- Trigger
- Jobs and Steps
- Checks
- Tests
- Behavior on Failure
- Permissions
- Using Secrets
- Deployment Presence

#### Constraints

- Do not create a hypothetical workflow.
- Do not print secrets.
- Do not report a test as successful without verification.

#### Answer

My project has one GitHub Actions workflow:
```
.github/workflows/ci.yml
```
##### Triggers:

- Push events to the main branch.
- Pull requests targeting the main branch.

##### Jobs:

- backend-test: Checks out the repository, sets up Node.js, installs dependencies, runs Jest tests, and executes ESLint.
- backend-docker-build: Builds the Backend Docker image.
- backend-publish: Runs on pushes to main, authenticates with GitHub Container Registry, builds and tags the image, and pushes it.
- deploy-backend: Runs on pushes to main, configures SSH, tests the connection, copies the deployment script, and deploys the Backend.

The local quality gate checks Git whitespace, Bash syntax, ShellCheck, Terraform formatting, Docker Compose configuration, and GitHub Actions workflow syntax.

The Backend currently has a basic Jest test. Its test coverage needs improvement.

I need to verify that publishing and deployment depend on the successful completion of the required test and build jobs.

### Challenge 3 - Review failure behavior

#### Scenario

Assume a Bash script contains a syntax error.
We want to ensure that the syntax check detects this error.

#### Task

Create a temporary test file with invalid syntax inside the `scripts/` directory.
Then, run the local CI script and verify that:
1. The error is detected.
2. The result is recorded as a failure (FAIL).
3. The script’s exit code is non-zero.
4. The test file is deleted.
5. The local CI script is executed again after the test file has been removed.

#### Constraints

Use a temporary, harmless file. Do not intentionally corrupt actual project files, and do not commit the test file to Git.

#### Answer

My first failure-injection test did not behave as expected.

I need to distinguish between a Bash syntax error and a runtime error. bash -n checks syntax without executing commands. Therefore, an unknown command name may pass the syntax check but fail at runtime.

I will create a temporary Bash file with invalid syntax, run the local quality gate, verify that the Bash syntax check fails, and confirm that the overall script returns a non-zero exit code.

I will then remove the temporary file and run the quality gate again.

### Challenge 4 - CI Security Review

#### Task

If GitHub Actions are present in the project, review the workflow(s) for the following:
- Necessity of each permission
- Usage locations of secrets
- Prevention of sensitive values being printed in logs
- Separation of CI from deployment
- Workflow failure when required checks fail

If no workflow exists, record this finding and provide a brief list of criteria required for a secure workflow.

#### Answer

The workflow uses the automatically generated GITHUB_TOKEN for GitHub authentication.

It also uses:

- DEPLOY_SSH_KEY for SSH authentication.
- DEPLOY_KNOWN_HOSTS for verifying the remote SSH host.

The jobs have contents: read. The publishing job also has packages: write.

I need to verify whether the deployment job actually requires package write access or only package read access.

The publishing and deployment jobs are restricted to pushes to the main branch. However, I must also verify their needs dependencies to ensure they cannot run before the required tests and build have succeeded.

A skipped job due to an if condition does not necessarily mean the entire GitHub Actions workflow has failed. I must distinguish an intentional skip from a failed required check.

**Note:**
- Check bash syntax error: `bash -n file.sh`.
- Check runtime error: `bash file.sh`.
- Get shellcheck result for a file: `shellcheck file.sh`.
- Get actionlint for a file: `actionlint -color .github/workflows/ci.yml`.
